# 01. 方針と状態モデル

## アプリの目的（設計の前提）

2,000 枚前後の写真から「残す数十枚」を、**人の目で・短時間で・迷わず**選び切る。
目の前の N 枚を見比べて 1 枚（または数枚）を選ぶ相対比較を繰り返す（トーナメント）。
勝ち残った回数 ＝ 星の数。AI は連写をまとめて「見る枚数を減らす」ことにだけ使う。

利用者が達成したいこと（優先順）:
1. 短時間で選び切る
2. 見比べて判断できる（写真が大きく、明るさが正しい）
3. 間違えたら戻せる
4. 中断して後で続けられる
5. 結果を取り出せる
6. 原本が無事だと確信できる

## 状態モデル

### プロジェクトの出所 `project.source`（D-1 の解）

```ts
type Source =
  | { kind: 'folder';     label: string; path: string }                 // PC
  | { kind: 'album';      label: string; albumId: string }              // Android MediaStore
  | { kind: 'nas';        label: string; nasId: string; share: string; path: string } // Android SMB
  | { kind: 'imported';   label: string; count: number }                // Web IndexedDB
```

- `label` は人間の言葉（フォルダ名／アルバム名／「home-nas · Share / 2021_06_13」）。生パスは「技術情報」だけに出す。
- 「NAS に接続中か」という別の状態を UI に出さない。接続は `nasId` ごとの状態（`connected | disconnected | error`）として設定画面と作成シートのタブで示す。
- 作成シートの一覧は **選択中のタブの出所からだけ**取得し、タブ切替時に必ず取り直す。

### 準備 `project.prep`（D-2 の解）

3 本の裏作業を 1 つのオブジェクトで持ち、**プロジェクト ID で作り直す**（前のプロジェクトの値が残らないように）。

```ts
type Prep = {
  scan:  { state: 'idle'|'running'|'done'|'error'; done: number; total: number|null } // 走査。total は完了まで null
  meta:  { state; done; total }   // 撮影時刻・サムネイル
  preview: { state; done; total; size: 768|1024|1280|1536|1920 } // 表示用画像
}
```

- 表示は常に `done / total`。`total` が未確定（走査中）のときだけ「120 / ?」。`indeterminate` は「接続しています…」の数秒だけ。
- **走査が `done` になるまで選別は開始できない**（枚数と時間順が確定しないため）。`meta` / `preview` は未完でも開始できる。

### 写真 1 枚の準備状態（D-4 の解）

`photo.previewState: 'ready' | 'generating' | 'queued' | 'failed' | 'unsupported'`
一覧の空タイルはこの 5 状態で描き分ける（02 参照）。

### 選別 `project.selection`

```ts
type Selection = {
  phase: 'not-started' | 'learning' | 'previewing-bursts' | 'in-round' | 'round-complete' | 'finished'
  round: number            // 1..
  targetStar: number       // このラウンドで見ている星（★0, ★1, …）
  groupSize: number        // 2..4 (Android/Web) / 2..10 (PC)
  burstGrouping: boolean
  queue: GroupId[]         // このラウンドの残りグループ
  current: { groupId; selected: PhotoId[] }   // 複数選択の途中状態も保存
  history: Decision[]      // 「1 つ戻す」用。ラウンドをまたげる
  learning?: { answered: number; answers: boolean[] }  // 基準学習の途中
}
```

- 保存単位：グループ確定ごと＋`current.selected` の変化ごと。← / システムバック / 終了 / 端末の開閉、どれでも失わない。
- `phase: 'round-complete'` のまま終了したら、再開時にラウンド完了シートから始まる。
