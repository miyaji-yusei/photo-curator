# 06. 画面遷移と、どの絵を使うか（実装前の確認）

Claude Design の資料を正とする。ここは**実装の契約**として、遷移と「各画面が
どの大きさの絵を読むか」を 1 か所に書き出したもの。設計から変える点は
理由つきで明記し、それ以外は設計のままにする。

## 2. 画面遷移

```
ホーム
 ├ ギア ────────→ 設定 ─→ nasEditSheet
 ├ ＋ ──────────→ createSheet ─(作成)→ プロジェクト詳細
 └ カード ───────→ プロジェクト詳細

プロジェクト詳細
 ├ 主ボタン（状態で 1 つ）
 │   ├ 走査中 ………… 無効「走査中… 120 / ?」
 │   ├ 未開始 ………… 「選別を開始」┐
 │   ├ 途中 ……………「選別を続ける」┤→ startSheet（初回、または「毎回確認」on）
 │   │                                └→ 連写まとめ on かつ基準未学習
 │   │                                     ├ はい → burst-threshold → burst-preview → 選別
 │   │                                     └ いいえ → 選別
 │   └ 完了 …………… 「結果を見る」→ results
 ├ 「…」 ────────→ 再読み込み／表示用画像の大きさ／名前を変更／技術情報／削除
 ├ 星の行 ────────→ results（その星で絞った状態）
 └ 一覧のタイル ──→ zoom（「残す」を出さない）

選別（tournament）
 ├ ← ────────────→ プロジェクト詳細（中断。毎回保存しているので確認は出さない）
 ├ タイル タップ ─→ 確定して次へ（複数モードでは選択）
 ├ タイル 長押し ─→ zoom（「残す」を出す）
 ├ ⧉N バッジ ────→ burstEditSheet
 ├ 「…」 ────────→ optionsSheet（表示枚数・連写まとめ・表示用画像の大きさ）
 └ 最後の組を確定 → roundCompleteSheet
        ├ 「★n を選別する」→ 選別（次のラウンド）
        └ 「ここで終えて結果へ」→ results

results
 ├ 星チップで絞る／並び替え（星が高い順・撮影順）
 ├ タイル 長押し ─→ 複数選択
 ├ 主ボタン「[対象] を…」→ outputMenu →（原本を変えるものは confirmDialog）→ 実行
 ├ タイル タップ ─→ zoom（「残す」を出さない）
 ├ 連写の組 タップ → burst-review（選別画面と同じ部品）
 └ 「…」 ────────→ 最初からやり直す（confirmDialog）／ROUND を 1 つ戻す／技術情報
```

「1 つ戻す」はラウンドをまたげる。ラウンド完了シートが出た状態で終了したら、
再開時は同じシートから。基準学習の途中で終了したら、答えた分から続ける。

## 3. 絵は 3 段階

| 段 | 何 | 大きさ | 実測 | 作る場所 |
| --- | --- | --- | --- | --- |
| **サムネイル** | EXIF の縮小画像 | 160×120 | 約 10KB | 準備 2 段目（指紋と同じ 1 回の読み） |
| **表示用画像** | 原本を縮小したもの | 長辺 1024 / 1536 / 768–1920 | 約 80KB（1024） | 準備 3 段目（原本を読むのはここだけ） |
| **原本** | そのまま | — | 6MB 前後 | 読むだけ・置かない |

- **端末のアルバムには表示用画像を作らない。** 手元のファイルは Coil が要求した
  大きさでデコードするので、置いても二重に持つだけになる。
- **NAS は必ず作る。** 原本 1 枚 6MB を網越しに読むので、表示のたびには使えない。

### どの画面がどれを読むか

| 画面 | 使う絵 | なぜ |
| --- | --- | --- |
| ホーム | 写真を出さない | カードは状態・進捗・次の一手だけ |
| 作成シート | 写真を出さない | フォルダ名と件数だけ |
| **プロジェクト詳細の写真一覧** | **サムネイル** | 96dp の格子を 187 枚。設計も「EXIF の 160×120 を使うため小さく表示」 |
| **選別（tournament）** | **表示用画像** | 判断する場所 |
| **連写の基準を学習** | **表示用画像** | 2 枚を大きく並べて判断する |
| **まとまりの確認** | **表示用画像** | ★設計は 72×54 だが、まとまりの良し悪しを見る場所なので落とさない |
| **まとまり編集シート** | **表示用画像** | 180×120 だが、代表を選ぶ判断をする |
| **連写の中身を選別** | **表示用画像** | 選別画面と同じ部品 |
| **選別結果の格子** | **表示用画像** | 4〜6 列＝200px 前後。星の確認と取り出しの判断をする |
| **拡大（zoom）** | **原本**（届くまで表示用画像） | 設計どおり。「原本を読み込み中 6.7MB · 表示用画像で先に表示」 |

**代用の順番はどの画面も同じ。**
表示用画像 → 無ければサムネイル → 無ければ「作成中／待機／読めません／非対応」のタイル。
準備の 3 段目が終わっていなくても、**粗くても出して選別は進められる**。

## 4. 端末に置くもの（出所ごと／プロジェクトごと）

| 置くもの | 単位 | 作り直す条件 |
| --- | --- | --- |
| 顔ぶれ（写真の一覧） | 出所ごと | **「写真を再読み込み」を押したときだけ** |
| サムネイル | 出所ごと | 原本の大きさが変わったとき |
| 指紋・撮影時刻 | 出所ごと | 版が変わったとき／原本の大きさが変わったとき |
| 表示用画像 | 出所ごと＋大きさごと | 大きさを変えたとき／無いとき |
| 星・履歴（選別の途中） | **プロジェクトごと** | やり直したとき |
| 連写の手直し（overrides） | **プロジェクトごと** | 手で直したとき |
| 学習した基準 | プロジェクトごと | 学習し直したとき |

- **出所ごと**にするのは、同じフォルダから 2 つプロジェクトを作っても
  絵と指紋を使い回せるようにするため。星は混ざってはいけないので分ける。
- **開くたびに網へ行かない。** 中身が変わったかはこちらからは分からないので、
  勝手に見に行かず、押されたときだけ数え直す。
- プロジェクトを消すときは、消える容量を言う（「表示用画像 15MB を消します」）。

## 5. 設計から変える点（前の会話で決めたこと）

| 変える点 | 設計 | 実装 | 理由 |
| --- | --- | --- | --- |
| **一度に見比べる枚数** | Android は 2〜4 | **2〜10（既定 4）** | 実際に 10 枚を使うため。設計も「幅と能力で決める」としている |
| **まとまり確認の一覧** | 72×54 のサムネ | **表示用画像** | まとまりの良し悪しを判断する場所なので画質を落とさない |
| **準備の 2 段目** | 「撮影時刻・サムネイル」 | 同じ。**指紋もここに含める** | EXIF の 1 回の読みで時刻・サムネ・指紋が同時に取れる |
| **表示用画像** | 全環境で作る | **NAS のときだけ作る** | 端末の写真は Coil が手元でデコードするので二重になる |
| **絵の取り違え防止** | （記載なし） | 型で 3 つに分ける | 前に選別画面が 160×120 を引き伸ばしていたため |

これ以外は設計のまま。

## 6. 実装の順番と、いまどこまで

| | 中身 | 実機で確かめたこと |
| --- | --- | --- |
| 1 | 結果を見るの遷移（完了なら結果へ直行） | ✅ 完了プロジェクトで開始シートが出ないことを確認 |
| 2 | 枚数 2〜10、表示用画像の「詳細…（768–1920）」 | ✅ 開始シートは**折り返して** 2〜10 を全部出す（1 行だと 6 以降が画面外だった） |
| 3 | まとまり編集シートを設計どおりに（区切り線＋代表、3 色巡回） | ✅ 凡例の名前は**まとまりだけで数える**（単独を数えて B・C・E と飛んでいた） |
| 4 | optionsSheet（選別中の「…」） | ✅ 6 枚に変えるとその場で 6 枚並ぶ |
| 5 | まとまり確認・結果・編集シートを表示用画像に | ✅ 選別画面と同じ絵 |
| 6 | zoom（表示用画像 → 原本で差し替え、拡大から「残す」、左右で前後） | ✅ 「原本を読み込み中 6.7MB」→「原本」。上端に暗い帯を敷かないと**白い写真で文字が消えた** |
| 7 | burst-review（連写の中身を選別） | ✅ 結果の ⧉N をタップ → 選別画面と同じ部品。★は組の中で上がる |
| 8 | ホームのカード 5 状態（準備中＝青・エラー＝赤）、空タイル 4 状態 | ✅ 完了カードは白＋星の内訳バー。準備中・エラーは端末に置いたものと「困りごと」から決める（**ホームは網へ行かない**） |
| 9 | 詳細の撮影時刻の範囲、「…」の表示用画像の大きさ、設定の状態の丸・版 | ✅ 大きさは**プロジェクトごと**（設定は新しいものの既定）。NAS の丸は「確認」を押したときだけ試す |
| 10 | confirmDialog を赤字・error 地に | ✅ 原本を書き換える操作だけ。やり直しは赤くしない |
| 11 | タイル右上の拡大・★5、長押しの献立 | ✅ ★5 は core の `keep_top`（survivors から外す・1 つ戻すで元の星に返る） |
| 12 | カバー画面（<600dp） | ✅ 詳細は縦積み、主ボタンは「落として次へ」に短縮 |

**11 と 12 は当初の書き方が設計とずれていた。**

- 11 の「縦横比から段を組む」は誤り。設計 `03-選別画面` は**枚数ごとの固定の行×列**（2→1×2、4→2×2、10→2×5…）を表で決めていて、実装もそれに従っている。画面の縦横比で使うのは「行と列を入れ替えるかどうか」だけ。
- 12 の「1 枚ずつ横スワイプ」も誤り。設計は <600px でも**同じ並べ方**（カバー・4 枚で枠 229×330）で、変わるのはカードの列数・バーのラベル・主ボタンの文言だけ。
