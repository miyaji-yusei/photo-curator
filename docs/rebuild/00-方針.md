# 00. 作り直しの方針

2026-09-07 決定。`feat/redesign` の作業はここでいったん止め、
**データの流れから設計し直す。**

---

## なぜ作り直すか

2026-09-06〜07 の実機検証で出た不具合を並べると、形が揃っている。

| 症状 | 実測 |
|---|---|
| 「172 件を解析できませんでした」が消えない | 解析は成功済み（`thumbnail_path` も `d_hash` も入っている）。**古いエラーだけが消し忘れられている** |
| プロジェクトを開くたびに解析が走る | 15 枚がエラーも無く未処理のまま。残作業が 0 にならない |
| 表示用画像が途中で止まる | 44 / 187 のまま **90 秒間まったく進まない**。エラーも記録されていない |
| 「作り直す」を押しても反応が見えない | 実際に何も動いていない。押した手応えも無い |
| サムネイルが更新されないことがある | 撮影時刻・サムネイルが 0/4、表示用画像は 4/4。片方だけ進んで止まる |

**3 つとも同じ形。裏の作業に「持ち主」がいない。**
誰が・いつ・どこまでやり、止まったら何を残し、次に何から再開するのか。
それが決まっていないので、止まっても誰も気づかず、成功しても後始末がされない。

**枠組みを変えても、ここを決めなければ同じことが起きる。**
だから画面ではなくデータの流れから書く。

## Android を作り直す理由（枠組みの話）

上とは別の話として、Tauri を Android に載せる税が大きい。
2026-09-06 の 1 日で踏んだものだけでも:

- `JNI_OnLoad` が無く JavaVM を取れない（起動直後に abort）
- `FindClass` がワーカースレッドで効かない（走査だけ失敗する）
- `convertFileSrc` が `content://` を扱えない（拡大表示が必ず壊れる）
- ステータスバーとの重なりで**メニューが押せない**
- APK 337MB、シンボリックリンクでビルド不能、JDK/NDK の手当て

**どれも写真アプリの本質と関係ない。** しかもこのアプリは
「大きな画像を並べる」のが本体で、WebView が一番苦手な領域。
MediaStore・SMB・Keystore・SAF は**すでに Kotlin で書いて JNI で運んでいる**ので、
ネイティブにすれば橋が丸ごと消える。

## 構成

```
core/            Rust。**判断が絡むものは全部ここ。**
  ├─ ffi/uniffi  → Android（Kotlin）
  ├─ ffi/wasm    → Web（ブラウザ）
  └─ ffi/tauri   → PC
app-android/     Kotlin + Jetpack Compose
app-desktop/     Nuxt + Tauri（枠組みは変えない）
app-web/         同じ Nuxt
```

### core に置くもの（1 つだけ書く）

- EXIF の解釈（撮影時刻・向き・埋め込みサムネイル）
- dHash と距離
- 連写のまとまり判定（時間窓 ＋ 距離、ペア例外）
- 選別（トーナメント・星・ラウンド・1 つ戻す）
- **データモデルと migration**
- **裏作業の状態機械**（何が終わっていて、次に何をするか）

### 各環境に任せるもの（得意な方でやる）

| | Android | PC | Web |
|---|---|---|---|
| バイトを読む | MediaStore / smbj | ファイル | File / Blob |
| 画像のデコードと縮小 | BitmapFactory（`inSampleSize`） | image クレート | `createImageBitmap` |
| 保存 | SQLite（Room ではなく core が持つ） | SQLite | IndexedDB |
| 画面 | Compose | Nuxt | Nuxt |

**デコードを各環境に任せるのは性能のため。** Android の
`BitmapFactory` はハードウェア支援とメモリプールがあり、Rust の
`image` クレートより速くて省メモリ。Web はブラウザ内蔵が最速。

**判断は core、入出力は端**。この線引きが要点。
不具合は判断のところに出るので、そこを 1 つにする。

### Rust を残す理由

「Rust を捨ててもいい」という話だったが、**捨てると共通化できない。**
Android ネイティブ＝Kotlin、PC/Web＝TypeScript となり、解析が 2 実装に割れる。
いまも Rust（PC）と TypeScript（Web）に**二重実装されていて**、
片方だけ直る不具合が実際に起きた。作り直しでここを 1 つに畳む。

## 決まっていること

| | |
|---|---|
| PC 版 | **Tauri + Nuxt のまま**作り直す。枠組みは変えない |
| Web 版 | 同じ Nuxt。PC と UI を共有する |
| Android | **Kotlin + Compose のネイティブ**に作り直す |
| 順番 | Android → PC・Web |
| **NAS のサイドカー** | **最初から設計に入れる。** あとから足すと持ち方が変わってしまう |
| 配色 | いまのダークテーマを踏襲（`docs/design/04-*` 参照） |
| 画面の構成 | Claude Design の設計書（`docs/Photo Curator 設計確認/`）を土台にする。**枠組みに依らない** |
