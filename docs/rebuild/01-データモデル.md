# 01. データモデル

**サイドカーを最初から織り込む。** あとから足すと持ち方が変わり、
移行のたびに新しい不具合が出る。

---

## 3 つの置き場

| 置き場 | 何を持つか | 誰のものか |
|---|---|---|
| **サイドカー** | 星・撮影時刻・dHash・連写の例外・選別の履歴 | **写真のフォルダ**。PC と Android で共有する |
| **端末の DB** | 手元のキャッシュと、その端末だけの都合 | 端末 |
| **端末のファイル** | サムネイル・表示用画像の実体 | 端末（消えても作り直せる） |

**判断の結果はサイドカーへ、作り直せるものは端末へ。**
この線引きで「端末を変えたら選び直し」がなくなる。

### サイドカーの置き場所

写真のフォルダの直下に `.photo-curator/` を作る。

```
2021_06_13/
  ├─ IMG_2224.JPG        ← 原本。**絶対に触らない**
  ├─ …
  └─ .photo-curator/
       └─ catalog.json   ← これだけ
```

**サムネイルと表示用画像はサイドカーに置かない。**
NAS に数百 MB を書くことになり、書き込み権限も要る。
原本のフォルダに増やすものは **1 ファイルだけ**にする。

---

## サイドカー `catalog.json`

```jsonc
{
  "version": 1,
  "updatedAt": 1788700000000,
  "updatedBy": "galaxy-z-fold-8",     // 競合したときに人が判断できるように
  "photos": {
    // キーは「フォルダ内の相対パス」。**端末ごとの URI ではない。**
    // content:// も smb:// も端末の都合なので、共有するものに混ぜない。
    "IMG_2224.JPG": {
      "capturedAt": 1623567000000,
      "capturedFrom": "exif_original", // exif_original | exif_datetime | filename | mtime
      "dHash": "3f8a…",
      "dHashVersion": 2,
      "rating": 3,
      // 原本が差し替わったかの手がかり。**サイズと更新時刻。**
      "size": 6423269,
      "mtime": 1623567012000
    }
  },
  // 連写のまとめ方に対する人の判断。まとまりそのものは閾値から導くので持たない。
  "burstOverrides": [
    { "left": "IMG_2224.JPG", "right": "IMG_2225.JPG", "decision": "split" }
  ],
  "sessions": {
    // 選別の途中。**端末をまたいで続けられる。**
    "tournament": {
      "phase": "in-round",
      "round": 2,
      "targetStar": 1,
      "groupSize": 4,
      "burstGrouping": true,
      "queue": ["IMG_2231.JPG", "…"],
      "current": { "group": ["…"], "selected": ["…"] },
      "history": [ /* 1 つ戻す用 */ ]
    }
  }
}
```

### 書き込みの規則

- **原本には絶対に書かない。** 増やすのは `.photo-curator/catalog.json` だけ
- 書き込みは**まとめて**（§02 の「いつ書くか」）
- 書く前に `updatedAt` を読み直し、**自分が読んだときより新しければ競合**
- 競合したら**両方を残す**（`catalog.json` と `catalog.<端末名>.json`）。
  黙って上書きしない。人が選べるようにする
- サイドカーが書けない（読み取り専用の共有など）ときは**端末だけで完結**し、
  「この端末だけの結果」と画面に出す

## 端末の DB

サイドカーの内容をそのまま持つのではなく、**手元で速く引くための形**にする。

```sql
-- 選別の単位。フォルダ 1 つにつき 1 つ。
CREATE TABLE projects (
  id             TEXT PRIMARY KEY,
  name           TEXT NOT NULL,     -- 人が付けた名前
  source_kind    TEXT NOT NULL,     -- folder | album | nas | imported
  source_label   TEXT NOT NULL,     -- 人の言葉（アルバム名・NAS のラベル）
  source_ref     TEXT NOT NULL,     -- 端末ごとの指し先（content:// smb:// パス）
  created_at     INTEGER NOT NULL,
  updated_at     INTEGER NOT NULL,
  -- サイドカーとの同期。**どこまで取り込んだか。**
  sidecar_read_at   INTEGER,
  sidecar_wrote_at  INTEGER,
  sidecar_state     TEXT NOT NULL DEFAULT 'unknown'  -- unknown | ok | readonly | conflict | absent
);

CREATE TABLE photos (
  id             TEXT PRIMARY KEY,
  project_id     TEXT NOT NULL,
  -- **共有するときの名前。** サイドカーのキーと同じ。
  relative_path  TEXT NOT NULL,
  -- **この端末での指し先。** 共有しない。
  source_ref     TEXT NOT NULL,
  name           TEXT NOT NULL,

  -- サイドカーから来る／へ行くもの
  captured_at    INTEGER,
  captured_from  TEXT,
  d_hash         TEXT,
  d_hash_version INTEGER,
  rating         INTEGER NOT NULL DEFAULT 0,

  -- 原本が差し替わったかの手がかり
  size           INTEGER,
  mtime          INTEGER,

  -- 端末だけのもの（消えても作り直せる）
  thumb_path     TEXT,
  thumb_of_size  INTEGER,   -- 作ったときの size
  thumb_of_mtime INTEGER,   -- 作ったときの mtime
  display_path   TEXT,
  display_edge   INTEGER,
  display_of_size  INTEGER,
  display_of_mtime INTEGER,

  is_missing     INTEGER NOT NULL DEFAULT 0,
  UNIQUE(project_id, relative_path)
);

-- **裏作業はテーブルで持つ。** 誰が持ち主かを DB に書く（§03）。
CREATE TABLE jobs (
  project_id  TEXT NOT NULL,
  kind        TEXT NOT NULL,   -- scan | meta | hash | display | sidecar
  state       TEXT NOT NULL,   -- idle | running | paused | done | failed
  done        INTEGER NOT NULL DEFAULT 0,
  total       INTEGER,         -- 確定していなければ NULL
  -- 失敗の理由。**成功したら必ず消す。**
  failure     TEXT,
  failed_at   INTEGER,
  -- 中断したところ。次はここから。
  cursor      TEXT,
  updated_at  INTEGER NOT NULL,
  PRIMARY KEY (project_id, kind)
);

-- 1 枚ごとの失敗。**枚数を数えるためではなく、理由を出すため。**
CREATE TABLE photo_failures (
  photo_id   TEXT PRIMARY KEY,
  kind       TEXT NOT NULL,   -- meta | hash | display
  reason     TEXT NOT NULL,   -- unreadable | unsupported | decode | timeout
  detail     TEXT,            -- 技術的な文言。「詳細」を開いたときだけ出す
  failed_at  INTEGER NOT NULL
);
```

### いまの形から変えたところと、その理由

| 変えたこと | いまの問題 |
|---|---|
| `analysis_error` を `photo_failures` に出す | 写真の行に混ぜていたため、**成功したときに消す責任が曖昧**だった。実機で 172 枚が「成功しているのにエラーが残る」状態になった |
| `jobs` テーブルを作る | 裏作業の状態がメモリ上の `HashSet` にしかなく、**アプリを閉じると消えた**。止まったのか終わったのかも区別できなかった |
| `thumb_of_size` / `thumb_of_mtime` を分ける | 「サムネイルを作ったときの原本」と「いま見えている原本」を別に持つ。1 つの fingerprint を使い回していたため、**作り直しの要否が判定できなかった** |
| `relative_path` を共有の鍵にする | `content://` や `smb://` は端末の都合。共有するものに混ぜない |
| `source_ref` を `folder_path` から分ける | 人に見せる名前（`source_label`）と機械の指し先を分ける |

---

## 「作り直しが要るか」の判定

**1 つの規則にする。** いまは fingerprint 1 つで 3 種類を判定していて、
どれかが古いともう一方も作り直され、逆にどれも作り直されないことがあった。

```
サムネイルが使える = thumb_path があり
                    thumb_of_size == size かつ thumb_of_mtime == mtime
表示用が使える     = display_path があり display_edge == 要求サイズ かつ
                    display_of_size == size かつ display_of_mtime == mtime
dHash が使える     = d_hash があり d_hash_version == いまの版
```

**それぞれ独立に判定する。** 表示用の大きさを変えてもサムネイルは作り直さない。
原本が差し替わったら 3 つとも作り直す。

## 移行

いまの DB は捨てず、**読めるところだけ引き継ぐ**。

- `photos.path` → `source_ref`、`relative_path` はそのまま
- `rating` `captured_at` `d_hash` は引き継ぐ
- `thumbnail_path` `display_path` は**捨てる**（作り直しの判定材料が無いため）
- `analysis_error` は**捨てる**（信用できないことが実測で分かっている）
- 選別セッションは捨てる（形が変わる）

引き継ぎは **1 回だけ**、新しいアプリの初回起動時に行う。
